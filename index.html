Abstract

Papyrus Papers is a native, local-first Mac workspace for researchers who live with PDFs over time. A paper can enter as a PDF, DOI, arXiv ID, BibTeX, or RIS record; become a searchable library item with editable metadata; open in a native reader; collect highlights, annotations, and Markdown + LaTeX notes; join a project with roles and evidence; then leave as BibTeX, RIS, CSL JSON, Markdown, or a project bundle. There is no account, no subscription, and no telemetry. Your library stays on your Mac unless you choose your own WebDAV sync.

Keywords — PDF library · native reader · Markdown notes · Evidence Board · Smart Collections · WebDAV sync · BibTeX / RIS / CSL JSON

One Library

A paper should not fragment into separate tools. The PDF, metadata, reading progress, tags, notes, project role, evidence, and citation key all belong to the same object. Papyrus Papers keeps that object coherent from first import through the final export.

The example throughout this page follows a single Nature article: A 5.3-million-year-old deep-sea whale necropolis in the Diamantina Zone. The same record appears in the library, opens in the reader, carries Markdown notes, supports a project archive, and exports through standard citation formats.

Capture & Organize

Import should produce a usable record, not a cleanup chore. Papyrus accepts PDFs, folders on Mac, DOI and arXiv identifiers, BibTeX, and RIS. It can read embedded PDF metadata, fetch scholarly metadata, and keep field-level provenance so you can see where a title, author list, year, DOI, or abstract came from when sources disagree.

Organization has several layers because research changes shape over time. Tags describe topics. Folders keep stable archives. Smart Collections stay current as saved filters. Projects gather papers for a draft, review, or literature archive without forcing the global library to mirror a manuscript outline.

Read & Annotate

Reading happens in a native window, not a web viewer embedded in a database. On Mac you can highlight, underline, strike through, draw freehand ink, leave notes, and set bookmarks. The reader remembers progress and keeps annotations attached to the paper instead of scattering them into a separate notebook.3

Figure-heavy articles need more than a citation key. Papyrus lets the article page, the figure, the reading note, and the eventual claim remain adjacent. A Markdown notes pane renders headings, lists, tables, code, and LaTeX math, so a figure comment or draft-ready interpretation stays beside the source that prompted it.

Projects & Evidence

Projects turn a library into a working argument. A paper can belong to several projects, and each project can give that paper a different role. The Nature article can be an anchor source in a Diamantina whale-fall archive, while adjacent papers provide ecological context, dating methods, or organism-specific background.

The Evidence Board is the place where Papyrus goes beyond storing citations. Each evidence item records the claim you are making, the quote or observation that backs it, your interpretation, the page, the citation key, a section role, and a confidence score. A project starts to read like an argument before the manuscript exists.

Search, Sync & Privacy

A research desk has to be searchable and inspectable. Papyrus indexes titles, metadata, notes, annotations, and extracted PDF text so a phrase can lead back to the paper, page, and context where it was useful. The reading queue keeps active work visible, while filters and Smart Collections surface papers by tag, journal, year range, favorite status, document type, or PDF availability.

Local-first is the default, not an add-on. Your library, PDFs, notes, annotations, search index, and project evidence live on your Mac. There is no Papyrus account and no telemetry. Network access is limited to actions you choose, such as metadata lookup or sync. Sync, when enabled, uses your own WebDAV destination and keeps dated restore points so a synced library can be inspected before it is restored.4

Export & Citation

The exit path is as important as the import path. A single paper or a whole project can leave as BibTeX, RIS, CSL JSON, Markdown, or a full bundle. Project export can include papers, notes, evidence, citations, and a report that flags missing PDFs, duplicate cite keys, sparse metadata, or unresolved citation problems before you hand work to another tool.
